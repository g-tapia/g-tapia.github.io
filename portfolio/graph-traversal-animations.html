Graph Traversal Animation Project

This project, PathfindingApp, was developed prior to the widespread availability of generative AI tools such as GPT and was built entirely from my own ideas and experimentation. The goal was to challenge my programming abilities by designing and implementing an interactive system that visualizes graph traversal and pathfinding algorithms from the ground up, without relying on tutorials or reference implementations.

Because this project was developed before tools like GPT were available, I had to independently research libraries, understand how their functions operated, evaluate required arguments, and experiment with their behavior to achieve the desired results. This process required hands on exploration and continuous adjustment, reflecting the type of problem solving expected from a developer working without predefined guidance.

The application enables users to explore and understand algorithms such as Breadth First Search (BFS), Depth First Search (DFS), Dijkstra’s Algorithm, A* Search, and others through real time animation. Users can define start and goal state nodes, adjust execution speed during runtime, resize graph components, and pause or resume the animation at any point to analyze the algorithm’s behavior step by step.

A significant portion of the work involved designing both the system architecture and the user interface. With no reference projects available, I relied on structured debugging and iterative testing to resolve issues related to state management, rendering performance, and user interaction. This required careful analysis and persistence to ensure the system behaved correctly across different scenarios.

This was a demanding project that involved a substantial amount of code and iterative debugging. It reflects the effort required to build a fully functioning, interactive application from scratch. Despite the challenges, the process significantly strengthened my understanding of object oriented programming, data structures, and algorithm design.

Uses and Applications

Graph traversal and pathfinding algorithms such as DFS, BFS, Dijkstra’s Algorithm, A* Search, and Beam Search are widely used in real world systems where efficient navigation, exploration, and decision making are required.

  • Navigation systems such as GPS routing use algorithms like Dijkstra and A* to determine the shortest or fastest path between locations
  • Network routing relies on traversal algorithms to efficiently transfer data between nodes across large systems
  • Artificial intelligence and game development use pathfinding to guide characters and simulate intelligent movement
  • Search engines and recommendation systems use graph based approaches to explore relationships between data points
  • Robotics and autonomous systems use these algorithms to plan movement and avoid obstacles in dynamic environments

Each algorithm offers different strengths depending on the problem. Some prioritize completeness and accuracy, while others focus on speed and efficiency. This project demonstrates how these tradeoffs affect real time decision making and system behavior.

The application is designed as an interactive learning tool, giving users the ability to adjust execution speed to match their learning style, modify inputs to test different scenarios, and pause the animation to predict what will happen next before continuing. Users can also redraw and resize the graph to improve clarity and better observe algorithm behavior based on their preferences.

Important Notes

Depending on the algorithm and its constraints, a path may not always be found. Some algorithms may prune or ignore paths that could lead to the goal state, especially when prioritizing speed or limiting the number of states explored.

Each algorithm evaluates and manages multiple possible paths at the same time. When a final path is displayed, it represents the best path selected from many alternatives considered during execution.

Algorithms & Animations

Breadth First Search

Breadth First Search (BFS) is a graph traversal algorithm that explores nodes in layers, starting from a given node and moving outward. It uses a queue to keep track of which node to visit next, ensuring that the first node added is the first one processed.

The algorithm begins by visiting the starting node and adding its neighbors to the queue. It then repeatedly removes the next node from the front of the queue, visits it, and adds its unvisited neighbors to the back. This process continues, expanding outward step by step, until all reachable nodes are explored or a target node (goal state) is found.

Breadth First Search guarantees the shortest path only when all edges have equal weight. In cases where edge weights differ, such as distances measured in miles, BFS no longer produces the optimal path.

This is because BFS treats every edge as having the same cost, focusing only on the number of steps taken rather than the actual distance traveled. As a result, it may return a path with fewer steps but a longer total distance.

For weighted graphs, algorithms such as Dijkstra’s Algorithm or A* Search are more appropriate, as they take edge weights into account when determining the most efficient path.

Depth First Search (DFS)

Depth First Search (DFS) is a graph traversal algorithm that explores a path as deeply as possible before backtracking. It uses a stack, which follows a last in first out approach, meaning the most recently added state is explored first.

The algorithm begins at a starting state and pushes it onto the stack. It then repeatedly selects the state at the top, explores it, and pushes its unvisited neighbors onto the stack. This causes the search to follow one path deeply before returning to earlier states to explore alternative paths.

This approach allows DFS to efficiently explore large graphs, but it does not guarantee the shortest path. Because it focuses on depth rather than distance, it may travel far away from the goal state before eventually finding a solution.

DFS requires tracking visited states to avoid revisiting nodes and entering cycles. While it can be memory efficient compared to breadth based methods, it may still explore long and unnecessary paths depending on the structure of the graph.

Best First Search

Best First Search is a heuristic based search algorithm that uses a priority queue to explore the most promising states first. Each state is prioritized using a heuristic function h(n), which estimates how close the state is to the goal state. In this project, the heuristic can represent the distance in miles from the current state to the goal.

The algorithm begins at a starting state and adds it to the priority queue. At each step, it selects the state with the lowest heuristic value, meaning the state that appears closest to the goal, and explores it. It then evaluates its unvisited neighbors and adds them to the queue based on their heuristic values.

Because the algorithm always chooses the state that looks closest to the goal, it can move quickly in the right direction. However, it only considers the estimated distance to the goal and ignores the cost already traveled. This means it may follow paths that seem promising but are not actually efficient.

As a result, Best First Search does not guarantee the shortest path. Its performance depends heavily on the quality of the heuristic, and it may overlook better routes if they do not appear immediately promising. While it can be fast and effective in some cases, it trades accuracy for speed compared to algorithms such as Dijkstra’s Algorithm or A* Search.

Dijkstra’s Algorithm

Dijkstra’s Algorithm is a graph traversal algorithm used to find the shortest path in a weighted graph. It uses a priority queue to always explore the state with the lowest known path cost, denoted as g(n), which represents the total distance from the starting state.

The algorithm begins by assigning the starting state a cost of 0 and all other states a cost of infinity. At each step, it selects the state with the lowest g(n), visits it, and evaluates its neighbors. For each neighbor, the algorithm calculates the cost of reaching it through the current state and updates its cost if a shorter path is found.

As new states are discovered, the algorithm tracks their parent state, forming multiple potential paths that grow over time. If a state is reached through a more efficient path, its parent is updated to reflect the improved route. In the animation, different colored paths represent these competing routes, and the moving connection highlights when a more efficient parent is selected.

This process continues until the target state (goal state) is reached or all reachable states have been explored. Because the algorithm always expands the lowest cost path first, it guarantees the shortest path when all edge weights are positive.

While Dijkstra’s Algorithm is reliable and accurate, it can be computationally expensive for large graphs since it explores many possible paths. It also does not use a heuristic to guide the search toward the goal, which can make it less efficient compared to algorithms such as A* in certain scenarios.

A* Search

Combines cost and heuristic to guide search efficiently.

A* Search is a pathfinding algorithm that combines the strengths of Dijkstra’s Algorithm and heuristic based search. It uses a priority queue to explore nodes based on a total cost function defined as f(n) = g(n) + h(n), where g(n) represents the cost to reach the current state from the starting state and h(n) estimates the remaining cost from the current state to the goal state.

At each step, A* selects the state with the lowest total cost and explores its neighbors. If a more efficient path to a state is found, the algorithm updates its cost and parent, ensuring that the best known path is always maintained. This process continues until the target is reached.

A* is widely used because it can guarantee the shortest path when the heuristic is well chosen and does not overestimate the true cost. It is generally more efficient than uninformed search methods, but its performance depends on the quality of the heuristic and it can require significant memory to store explored states.

Beam Search

Beam Search is a heuristic based search algorithm that explores a graph by focusing only on the most promising nodes at each step. Instead of exploring every possible path, it maintains a limited set of candidates called the beam, which is controlled by a parameter denoted as β (beta). The value of β determines how many nodes are kept at each level of the search.

At each step, the algorithm evaluates neighboring states using a heuristic function h(n), where n represents a state. This heuristic is chosen based on the problem and can represent values such as the distance from a neighboring state to the goal state, or the cost from the current state to its neighbors. Based on this evaluation, only the β most promising states are retained.

All other states are pruned, meaning they are removed from consideration and will not be explored further. In this project, pruning occurs by keeping only the neighboring states with the lowest distance in miles, allowing the algorithm to focus on paths that appear more efficient.

This process continues iteratively, expanding only the selected states and repeatedly applying pruning at each level. By limiting the number of paths explored, Beam Search improves performance and reduces memory usage compared to more exhaustive algorithms. However, because it discards alternative paths early, it may miss the optimal solution or fail to find a valid path depending on the chosen β value and heuristic.

Beam Search Animation

In this demonstration, β = 1, meaning only one state is kept at each step. The algorithm first evaluates all neighboring states, then sorts them by the heuristic value, which in this case is the distance in miles relative to the current state. After sorting, only the most promising state is retained while all others are pruned from the path.

This is why the animation displays placement numbers such as 1, 2, 3 and so forth, above the states. Those numbers show the sorted order of the neighboring states before pruning occurs. The state marked 1 is at the front of the most promising set, so it is selected to continue the search while the remaining states are removed from consideration.

In this scenario, no solution is found. Because the beam width is limited to a single state, the algorithm prunes alternative paths that could have led to the goal state. This demonstrates a key limitation of Beam Search, where aggressive pruning can prevent the algorithm from reaching a valid solution.

In this demonstration, β = 3, meaning only three states are kept at each step.

Technical Details

The application is built using object oriented programming principles, combining graph data structures with traversal and pathfinding algorithms. Core components include adjacency representations of states, queues and stacks for traversal control, and priority queues for cost based and heuristic driven searches.

The system tracks multiple paths simultaneously, maintaining parent relationships to reconstruct routes and dynamically updating paths when more efficient options are found. Algorithms such as Dijkstra and A* compare path costs in real time, while others like Beam Search apply pruning techniques to limit the number of states explored.

The animation layer is tightly integrated with the algorithm logic, requiring synchronization between state updates and visual rendering. This includes managing node states, color transitions, path highlighting, and visual indicators such as rankings and parent changes to accurately reflect algorithm behavior during execution.

Challenges

One of the primary challenges was synchronizing traversal logic with animation rendering in real time. Ensuring that each step of the algorithm was accurately reflected visually required careful control of state transitions and timing.

Another challenge involved managing the complexity of multiple paths being evaluated simultaneously. Since many algorithms track and update paths dynamically, it was necessary to design a system that could efficiently handle parent updates, path comparisons, and pruning without breaking visual consistency.

This project was developed without reference implementations, which required independently researching libraries, understanding their behavior, and experimenting with different approaches to achieve the desired animation and interaction. Debugging complex interactions between algorithm logic and visualization required iterative testing and problem solving.
